# v0.2 Working Model

Status: **validated revision candidate; v0.2 gate passed**<br>
Date: **2026-08-15**

## Result that forces revision

The original strong claim was:

> Four unavoidable constraints—Cost, Compatibility, Continuity and
> Cognition—explain the Harness layer.

Hostile tests found three Harness-level residuals after holding all four causes
constant:

- **Epistemic Access:** the model cannot use evidence it does not observe.
- **Validity:** a technically valid and authorized proposal can still be wrong.
- **Authority:** a correct proposal can still be unauthorized.

Reliability, Coordination, Planning and generic Control did not survive the
same independence test. The honest response is not to expand an existing C
until it contains the residuals. It is to narrow what 4C claims.

## Defensible 4C claim

> **4C is a 3 + 1 model: resource scarcity, semantic heterogeneity and temporal
> extension are operational pressures on Harness execution policy; Cognition is
> the feedback plane that changes future policy from accumulated experience.**

Formally, let an execution policy choose actions or transitions from available
observations and constraints:

``` text
π: (intent, evidence, state, events, policy) → candidate transition set
```

`3 + 1` classifies three current pressures on `π` and one way it can change
across executions:

| Dimension | Reality | Policy variation |
|---|---|---|
| Cost | Resources are finite. | Change model, context, route, concurrency, attempts or stopping because resource conditions differ. |
| Compatibility | Systems are heterogeneous. | Change representation, capability use, target or fallback because interfaces/semantics differ. |
| Continuity | Tasks outlive bounded calls and attempts. | Change/preserve state and lifecycle transitions because execution extends through time. |
| Cognition | Prior execution produces reusable evidence. | Change future policy because experience supports evaluation, diagnosis or learning. |

These dimensions are conditional rather than universal per instance. “Cost” is
shorthand for resource scarcity, not money alone. Each pressure counts only
where it changes task-level policy; compute optimization, protocol plumbing,
persistence substrates and model training do not become Harness work merely by
sharing its vocabulary.

Cognition is not a peer constraint. A static Harness can execute without
learning, while the other three can make a current intended execution infeasible
or semantically broken when activated. Cognition remains in the model because a
systematic cross-run policy delta is a distinct Harness mechanism and source of
variation.

This is still falsifiable. A new **operational pressure or feedback dimension**
would require an independent reality that explains policy variation and is not
an evidence/mediation obligation, desired outcome or mechanism.

The system is recursively closed over policy changes: a prompt, skill, validator
or permission delta is itself a candidate transition over a versioned artifact.
It must pass evidence, Validity and Authority checks before application. A
Cognition loop cannot define its own root success predicate or self-authorize;
those roots are fixed by the Application/principal boundary for the execution
being analyzed.

## Explicit non-claims

4C does not currently claim:

1. to enumerate every Harness requirement;
2. to describe every stage in an execution lifecycle;
3. to guarantee correctness, safety, security or reliability;
4. to classify model intelligence or Application goals;
5. to absorb information access, result validity or action authority;
6. to imply that every Harness instance activates all four dimensions;
7. to provide a universal maturity ladder or task-free product score.

These are boundaries, not escape hatches. If 4C is marketed as a complete
Harness taxonomy, the authority, validity and context attacks falsify it.

## Execution model: mediated transition system

``` text
APPLICATION: intent · success predicate · authority policy
                              │
                              ▼
┌────────────────────────── HARNESS ──────────────────────────┐
│  state + available evidence + events                        │
│             ▼                                               │
│  select candidate(s) ← model · code · human · event         │
│             ▼                                               │
│  mediate boundary             ← Validity · Authority        │
│             ▼                                               │
│  apply or expose transition(s) → tool · state · output      │
│             │                                               │
│             └── outcome / event / error ──► observe/update ─┘
│                                                             │
│  operational plane: Cost · Compatibility · Continuity       │
│  feedback plane: Cognition                                  │
└─────────────────────────────────────────────────────────────┘
```

The diagram is causal, not a required module layout. Zero, one or many
transitions may be in flight; a sequential loop is only one topology. A single function may
retrieve evidence, validate it, check permission and execute a tool. Mediation
can occur when accepting input, before or after a tool, before exposing output,
or while resuming. The earlier linear pipeline was falsified because these
boundaries recur and transition selection is not always performed by a model.

## Boundary obligations

### Observation

**Question:** What task-relevant, sufficiently fresh and attributable evidence
can selection, inference and mediation condition on now?

Mechanisms include retrieval, search, environment inspection, memory read,
tool-result shaping, pruning and prompt/context assembly.

Observation interacts with 4C:

- compress because capacity is finite → Cost;
- translate a source representation → Compatibility;
- restore prior task state → Continuity;
- learn better retrieval policy → Cognition.

None explains the minimal need to acquire an unobserved current fact.

### Mediation: Validity

**Question:** Does the evidence, candidate transition or observed outcome
satisfy the task's acceptance predicate with adequate integrity?

Mechanisms include schema plus semantic validation, assertions, tests, critics,
result comparison, task-completion checks and escalation.

The Application usually supplies the predicate; the Harness applies it before
application, after observing an effect, or before exposing output. Application
does not prove that the intended postcondition occurred.

### Mediation: Authority

**Question:** May this authenticated principal and delegation cause or expose
this effect, for this scope and audience?

Mechanisms include capability restriction, credentials, sandboxing, allow/deny
policy, approvals, provenance and audit.

External systems may define or enforce parts of the boundary. The Harness-owned
part is the mediation from proposed action to dispatch, rejection or escalation.

### Apply / expose

**Question:** How is an admitted transition applied while preserving task
semantics?

Application uses tools and runtime/infrastructure primitives. Retry, idempotency,
checkpointing, compensation and recovery are primarily Continuity at task
granularity. The database, worker or sandbox implementation may remain outside
the Harness.

## Why these are not simply three more Cs

The attacks did not discover three more equivalents of the `3 + 1` dimensions:

- Observation supplies inputs to policy and inference.
- Validity and Authority constrain commitment of proposals.
- the operational Cs explain current pressure; Cognition explains cross-run
  adaptation.

Adding Context, Correctness and Consequence to one flat seven-item list would
mix boundary stages with causal adaptation axes. It would be more complete as a
checklist but weaker as a theory.

The layered distinction remains provisional. It earns adoption only if it maps
real systems with less distortion and predicts failure modes better than a flat
list.

The model improves the earlier mapping by distinguishing transport of a decision
from the predicate that causes it. LangGraph can persist an approval without
defining who is authorized; a test can cause a Codex retry without being a
Continuity constraint.

## Tranche 02 boundary result

The second [system tranche](systems-tranche-02.md) mapped SGLang, Portkey, the
OpenAI Agents SDK, Claude Code and Braintrust at mechanism rather than product
level. It found no new residual, but forced two safeguards:

- a product may span Infrastructure, Harness and Application surfaces;
- the unit of execution must be named before applying the loop or 4C.

SGLang's inference runtime remains Infrastructure while its original frontend
language can orchestrate multi-call task execution. Portkey demonstrates
mediation at both request and response boundaries. Agents SDK and Claude Code
replicate mixed model/code/human transition selection. Braintrust demonstrates
that evaluation evidence is not Cognition until it changes future policy.

## Competing models still alive

### Flat expanded taxonomy

List Cost, Compatibility, Continuity, Cognition, Context, Correctness and
Consequence as peers. Advantage: simple checklist. Failure risk: mixes causes,
stages and outcomes.

### 4C plus cross-cutting invariants

Keep 4C flat and call Observation/Mediation external invariants. Advantage:
preserves branding. Failure risk: no uniform rule explains why Cost budgets are
inside while Authority policies are outside.

### Mediated transition system with 3 + 1 — current leader

Use a concurrent mediated transition system over state, evidence and events,
with three operational pressures and a Cognition feedback plane. Advantage:
handles repeated observation, input/tool/output mediation and mixed transition
sources. Failure risk: its operations may still be too generic to discriminate
Harness from ordinary workflow engines.

## Continuing tests after the v0.2 gate

1. Reproduce the completed multi-principal and self-modification attacks in
   additional independently implemented systems.
2. Continue adversarial replication beyond the completed Inngest/Temporal async
   pair and A2A/MCP multi-principal pair.
3. Reproduce the Cognition result in additional production systems: it survives
   as a feedback adaptation pressure only when past evidence changes future
   Harness policy; tracing or scoring alone does not qualify.
4. Continue the now-completed named concept tranche through
   counterexample-driven concepts rather than vocabulary collection.
5. Find systems that falsify the proposed Application/Harness/Infrastructure
   ownership split.

The original exhaustive theory remains rejected. This revised model has passed
the v0.2 desk-research gate; it is not yet the fully sourced, diagrammed and
empirically deepened v1.0 publication.
